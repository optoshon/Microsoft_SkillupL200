System Architecture

Two Phases, One Pipeline

Phase 1 — Indexing (Offline)

Knowledge Base

  • Load PDF, DOCX, CSV, TXT files
  • Split into overlapping chunks
  • Embed with all-MiniLM-L6-v2
  • Store in FAISS vector index
⟶
Phase 2 — Retrieval (Online)

Query Time

  • Embed the user's question
  • Cosine similarity search in FAISS
  • Retrieve top-K chunks
  • Score & rank results
⟶
Phase 3 — Generation

LLM Answer

  • Build a context-injected prompt
  • Feed to local GPT-2 model
  • Generate grounded response
  • Cite source documents

Load Documents
Load All Documents from Folder

The pipeline starts by scanning a references/ folder for supported document types. Each file is loaded using the appropriate LangChain loader, and the source filename is attached to every document's metadata for later traceability.

Python # Discover all supported files for ext in ['*.pdf', '*.docx', '*.csv', '*.txt']: all_files.extend(ref_folder.glob(ext)) # Load each file with the right loader if file_path.suffix == '.pdf': loader = PyPDFLoader(str(file_path)) elif file_path.suffix == '.docx': loader = Docx2txtLoader(str(file_path)) docs = loader.load() for doc in docs: doc.metadata['source'] = file_path.name # tag source
Supported FormatsPDF, DOCX, CSV, TXT — handled by loader-specific classes
Metadata TaggingFilename stored in metadata['source'] for attribution
OutputA flat list of Document objects with text + metadata

Chunk Split
Split Documents Into Chunks

Large documents are split into smaller, overlapping chunks so the embedding model can process them efficiently. Overlap ensures that context spanning a chunk boundary isn't lost.

Python text_splitter = RecursiveCharacterTextSplitter( chunk_size=500, # max chars per chunk chunk_overlap=50, # overlap between chunks length_function=len, separators=["\n\n", "\n", ". ", " ", ""] ) chunks = text_splitter.split_documents(documents)
💡 Why Overlap? If an answer spans two adjacent chunks, the 50-character overlap guarantees the boundary context appears in at least one chunk — preventing information loss at split points.
Chunk Size500 chars — balances context richness vs. embedding quality
Overlap50 chars — prevents lost context at boundaries
Split StrategyTries paragraph → line → sentence → word → char

Embed Vector DB
Generate Embeddings & Build Vector Index

Each chunk is converted into a dense numerical vector (embedding) using all-MiniLM-L6-v2. Semantically similar texts produce similar vectors. All vectors are stored in a FAISS index for lightning-fast nearest-neighbor search.

Python # Load the embedding model model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2") # Wrap with LangChain-compatible interface class SentenceTransformerEmbeddings: def embed_documents(self, texts): return self.model.encode(texts).tolist() def embed_query(self, text): return self.model.encode([text])[0].tolist() # Build FAISS vector store from chunks vector_store = FAISS.from_documents(chunks, embeddings)
🔷 What is FAISS? Facebook AI Similarity Search — an optimized library for finding the most similar vectors in a large collection in milliseconds, using approximate nearest-neighbor algorithms.
Modelall-MiniLM-L6-v2 — 384-dim, fast & accurate
Vector Dim384 floats per chunk
Index TypeFAISS flat index (exact L2 search)
4
🔍
Retrieve Similarity Search
Retrieve Relevant Chunks

At query time, the user's question is embedded into the same vector space. FAISS then finds the top-K chunks whose vectors are closest to the query vector — these are the most semantically relevant passages.

Python query = "What is the sick leave policy?" # Retrieve top-3 most similar chunks retrieved_docs = vector_store.similarity_search(query, k=3) # Also get the distance scores (lower = closer) retrieved_with_scores = vector_store.similarity_search_with_score( query, k=3 ) for doc, score in retrieved_with_scores: print(f"{doc.metadata['source']}: {score:.4f}")
⚠️ Score Interpretation FAISS returns L2 distance scores — lower values mean higher similarity. A score near 0 means near-identical content. Scores above ~1.5 usually indicate a poor match.
Query EmbeddingSame model as indexing — ensures comparable vectors
Top-KConfigured as 3 (tunable in CONFIG)
Distance MetricL2 (Euclidean) — lower = more similar

Generate Local LLM
Generate Answer with Local GPT-2

A local GPT-2 model is loaded from HuggingFace and used to generate the answer. The retrieved chunks are assembled into a context block, combined with the question into a prompt, and passed to GPT-2 for text generation.

Python # Load GPT-2 (auto-cached after first run) tokenizer = AutoTokenizer.from_pretrained("gpt2") model = AutoModelForCausalLM.from_pretrained("gpt2") generator = pipeline("text-generation", model=model, tokenizer=tokenizer, device=0 if torch.cuda.is_available() else -1) # Build context from retrieved chunks context = "\n\n".join([ f"[Source: {d.metadata['source']}]\n{d.page_content}" for d in retrieved_docs ]) out = generator(prompt, max_new_tokens=150, temperature=0.7, top_p=0.9)
💡 Local vs. API GPT-2 runs entirely on your machine — no internet, no API costs. It's less capable than GPT-4, but perfect for demos, privacy-sensitive data, and air-gapped environments.
ModelGPT-2 (117M params) or GPT-2 Medium
SamplingTemperature 0.7 + Top-p 0.9 for diverse outputs
GPU SupportAuto-detects CUDA, falls back to CPU

📝
Prompt Template
Build the RAG Prompt

A carefully structured prompt template injects the retrieved context alongside the question. The instruction tells the model to answer using only the provided context, preventing hallucination by constraining the generation space.

Prompt Template # Format retrieved chunks as numbered context blocks context_text = "\n\n".join([ f"[Context {i+1}]\n{doc.page_content}" for i, doc in enumerate(retrieved_docs) ]) rag_prompt = f""" Answer the question using ONLY the context below. If the context does not contain the answer, say: "I don't know based on the provided context." Context: {context_text} Question: {query} Answer: """
🔷 Prompt Engineering Key The phrase "using ONLY the context below" is critical — it instructs the LLM to ground its answer in the retrieved documents rather than its own parametric knowledge, enabling factual, auditable responses.
Grounding Instruction"ONLY the context below" — prevents hallucination
Fallback PhraseExplicit unknown response for out-of-scope questions
StructureContext → Question → Answer (clear separation)

✨
Answer Grounded
Generate & Display Final Grounded Answer

The RAG prompt is sent to GPT-2 for final generation. The model's output beyond the prompt is extracted as the answer, and the sources that contributed to the answer are printed for full traceability.

Python out = generator(rag_prompt, max_new_tokens=200, do_sample=True, temperature=0.7, top_p=0.9 ) # Extract only the generated portion (not the prompt) final_answer = out[0]["generated_text"][len(rag_prompt):].strip() print(f"Question: {query}") print(f"Answer: {final_answer}") # Always show which sources were used for d in retrieved_docs: print(" -", d.metadata['source'])
💡 Slicing the Output generated_text[len(prompt):] strips the prompt prefix from the output. HuggingFace's pipeline returns the full prompt + completion concatenated, so you must slice off the prompt to isolate just the new text.
Output ExtractionSlice [len(prompt):] to isolate generated text
Source CitationSources listed from retrieved chunk metadata
Max Tokens200 — gives room for a complete answer
Key Concepts

Glossary

RAG
Retrieval-Augmented Generation — a technique that combines a retrieval system (finding relevant documents) with a generative LLM to produce factually grounded answers.
Embedding
A dense numerical vector (list of floats) that represents the semantic meaning of a text. Similar texts produce similar vectors, enabling mathematical similarity comparisons.
FAISS
Facebook AI Similarity Search — a highly optimized library for fast nearest-neighbor search over large collections of dense vectors. Used here as the vector database.
Chunking
Splitting large documents into smaller, fixed-size pieces so each piece fits within an embedding model's token limit while preserving meaningful semantic units.
Chunk Overlap
A strategy where adjacent chunks share some content (e.g. 50 characters). This prevents context that spans a chunk boundary from being entirely lost.
Top-K Retrieval
Returning the K documents most similar to a query. A higher K gives more context but can dilute relevance; a lower K stays focused but may miss information.
Grounded Answer
An LLM response whose content is explicitly constrained to the provided context, rather than the model's own parametric memory — reducing hallucination risk.
Parametric Memory
Knowledge encoded in an LLM's weights during training. RAG supplements this with external, up-to-date, or domain-specific documents that weren't in the training data.
Temperature
A sampling parameter that controls randomness in LLM output. 0 = deterministic/factual, 1+ = creative/random. This pipeline uses 0.7 as a balanced middle ground.
